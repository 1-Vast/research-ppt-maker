# 从 DOI、论文名或项目到直观 PPT

## 输入入口

| 用户给什么 | 主动完成什么 | 何时才需要补问 |
|---|---|---|
| DOI / DOI 链接 | 规范化标识，核对题名和版本，定位原文、补充材料和官方资源 | DOI 无效且标题回查仍不能定位 |
| 论文名称 / 方法简称 | 完整标题优先检索，以作者、年份、任务及出版源消歧 | 多个候选确实会导向不同论文，无法用上下文区分 |
| PDF / 论文链接 | 从文件核对身份，寻找配套补充材料和清晰原图 | 缺失内容对关键方法或结果解释不可替代 |
| 项目描述 / 项目目录 | 先辨别构想或已实施项目，读取给定材料，检索背景与前作，组织方案或真实进展 | 核心目标有多种解释，或汇报既有工作所必需的事实在材料中缺失；已声明未实施时不索要代码和结果 |

不让用户先准备文献清单、原图、详细大纲或讲稿。未指定受众时可按有相关专业基础、未读过该论文的组会成员组织，说明假设后继续；未指定页数时，常规单篇论文交流按主技能默认 4–5 页，其他任务按实际内容确定，不为询问页数停工。

## 检索与原文阅读

1. **核对身份和版本。** DOI 通过 `doi.org`、出版社和 Crossref 等元数据核查；标题用精确题名检索。arXiv/OpenReview/PMC 等记录与正式发表版本核对作者、日期、版本和勘误信息，不拼接不同版本的图和数值。论文引用的最终版本优先；预印本独有内容要标明。
2. **找原文及配套材料。** 优先出版社全文、合法公开 PDF、作者主页或机构仓储、PMC/arXiv/OpenReview。阅读理解任务、方法和选用结果所需的正文、图注及补充；官方代码/项目页面用于核实实现和补充资源，不替代论文证据。不是只读摘要后生成整套细节。
3. **围绕理解缺口补检索。** 找任务定义、必要生物/数学背景，以及理解核心改变所需的前作或基线。资料数量取决于问题，不强制做全面文献调研。找到了足以支撑任务、方法、关键实验及边界的材料，就转入制作。
4. **取图并定位证据。** 可获取完成 PPT 所需的公开全文、补充文件、原图或相关小型资料到 `work/sources/`，记录原始 URL 和版本；无需为常规公开资料重复询问。HTML 图、PDF 面板和 source data 按实际可读性选择。读 PDF/处理图表时使用当前可用的对应技能与工具。
5. **处理访问或资料缺口。** 单一来源失败就记录限制，继续独立的合法公开版本；不反复撞同一失败接口，不绕付费、登录或验证。只有摘要时只作摘要支持的介绍，不能生成详细机制和结果。若关键内容始终缺失，明确受影响页面并询问必要材料，其余页面继续推进。

没有网页搜索工具时可用实际可用的官方公开 API 或 HTTP 读取；不得捏造检索记录。用户另行要求系统性调研时可调用 `lit-survey`，但普通单篇论文讲解不默认触发其完整调研与报告流程。

### 内部证据对应表

在 `work/` 保留简单表格或 JSON，字段按需要使用：

`页面 / 待支持的主张 / 图中讲解位置或检验方式 / 来源URL或DOI / 版本 / 章节-图号-面板或表号 / 实际读取范围 / 原图或改绘 / 观察与结论范围`

元数据命中不等于读过摘要，读过摘要不等于读过全文；只记录真实阅读范围。数字回查原始表/正文/source data，必要的计算注明公式。PPT 页脚保留简短来源（作者、年份、会议或 DOI/arXiv 号），不为参考文献另加页面；不要要求用户另读检索报告才能理解 PPT。

## 论文先理解，再设计页面

在做内容计划前先阅读 [teaching-first-workflow.md](teaching-first-workflow.md)，判别文章类型，并整理**领域发展脉络**（已有研究实际完成什么→新情境带来的问题→本文采用什么改变）。背景用真实相关工作及核实的事实，不从模型模块名称倒推出背景痛点。准备模型解剖表：输入、编码、核心交互、监督、推断与下游任务，并依据原文作者声称的贡献标识主次；不在主图上遮挡性编号。

制作前用内部笔记回答以下问题；它们用于防止“图看起来复杂，实际没讲清楚”，不交付成长篇文稿：

- **任务**：一个样本是什么，计量单位、聚合方式及样本间重复关系是什么；输入和输出是什么，什么条件让它困难？
- **已有做法**：解决到了哪一步，为什么当前条件下还不够？
- **核心改变**：作者到底改变了数据、表示、交互、目标、搜索还是评价中的什么？
- **机制**：关键模块如何作用于对象或表示，信息/梯度/反馈怎样传递，哪些量被共享、冻结或更新？
- **证据**：哪项实验支持有效性，哪项消融支持所声称的机制，比较是否同一协议？
- **边界**：关键假设、失败情形和未验证的推断是什么？

讲解必须忠实于实际论文；某些问题不适用时略过，不擅自给理论论文添加“训练阶段”，也不让实验论文凑神经网络模块。

## 从方法复述到研究解释

围绕决定论文价值的 1–2 个选择，先在内部写一条短论证，再决定放什么图。不要对每个模块都套模板，也不交付成讲稿。

| 必须弄清的内容 | 能改变页面决策的问题 |
|---|---|
| 实质差异 | 相对最相关且已核实的已有方案，具体改变了输入、目标、表示、交互还是假设？创新是新机制、组合方式、适用条件还是验证发现？ |
| 作用路径 | 哪个对象经什么运算或监督被约束，误差/信息/反馈作用于哪里，为什么可能影响目标能力？把原文结构事实与讲解性推断分开。 |
| 反事实预期 | 去掉、替换或错配这个设计，预期哪种能力改变？这是原文实验证实、理论推出，还是尚待验证？ |
| 判别证据 | 哪项实验检验总体效用，哪项真正区分上述解释？是否仍有训练量、数据来源、标签信息或目标形式等相关的替代解释？只检查影响当前结论的条件。 |

有必要时检索直接前作的原文，而非只引用作者“首次”或“传统方法不足”的概括。术语首次出现给出准确对象与作用，不用比喻替代机制，也不为显得深入罗列无关超参数。公式只保留能说明关键条件依赖、目标或约束的部分，紧邻解释符号与实际作用。

有连接、可访问某信息或存在梯度通路，不等于模型实际依赖该信息。讲清结构提供的路径、训练目标施加的优化压力、实验验证的实际利用这三者；未有判别证据时，不用“必然”“迫使”“损失下降就证明”替代解释。条件生成尤其要注意目标前缀等其他可用线索，避免把合理的设计意图写成已经保证的机制。

知识来源尤其要区分独立实验证据、元数据标签、计算推断和由输入派生的伪监督。来自同一输入的目标仍可能引入有效先验或归纳偏置，但不能自动称为新增独立事实。生成序列、注意力、相似度或嵌入结构是否有生物学含义，要按其构造和验证方式判断。

创新说明与证据强度匹配：整体消融支持整体方案的效果；分支贡献需对应移除/替换对照；“互补”“协同”“因果”“更高效”等更强主张需要能区分它们的证据。未提供的对照是尚未排除的解释，不等于证实方法无效。讲解者建议须标为建议，不能伪装成论文已有实验。

遇到消融表里的“w/o 模块”，回查方法与附录：实际改变的是训练目标、重新训练后的模型，还是同一模型的推断输入、打分或后处理？只把结果归因到真正改变的环节；推断时关闭一个分数项，不能直接证明相应训练目标的贡献。

### 有授权时的多代理迭代

当用户当次要求多代理协作，或当前会话已有明确的多代理授权时，主代理保留制作与合并职责，按实际难点分工：

- **原文与机制审查**：核查核心作用路径、相关前作差异和原文证据；指出具体主张及章节/图号。
- **独立质疑审查**：先看材料与任务，独立寻找解释断点、替代解释和过强结论；不先喂给预期答案，不把合理质疑写成已证伪。
- **叙事与视觉审查**：查看实际页图，核对有限页数内各页是否承担不同论证任务，图/公式/对比是否帮助追踪机制；避免只给美感评分。

代理只读共享源文件或写各自独立的工作目录，由主代理编辑成品与技能，避免并发覆盖。意见需定位到页面/主张/原文或具体理解缺口；主代理回查证据后决定采纳，不以代理人数表决事实。

先由独立审稿者对照原文审内容计划或旧稿，再让其看整合后的同一版成品与页图。审稿者给出页码、原文位置与具体缺失，主代理回查后修订并记录处理结果。将问题合并为必须修复、可选改善、不采用及理由；执行一轮定向修改，复审只查修复与受影响内容。核心事实、解释或可读性仍有缺陷时，再做一轮针对性修改。事实问题清零、下述内容验收和逐页视觉验收通过、没有新的具体重要缺陷时停止；不无限追求评分或继续加字加页。到本轮修订上限仍无法解决的问题应明确保留限制。

维护技能时，从真实使用失败中提炼最小通用修正，并由未参与改写的代理使用更新后技能与原始材料做内容计划或代表页的前向验证。普通小修不必启动完整验证。具体论文知识留在示范工作目录，不固化为所有论文必须满足的科学结论，也不自动创建后台任务或修改记忆。

## 把方法讲直观

### 一条稳定的具体例子

先给一个可看懂的输入/输出实例，再让同一实例贯穿需要解释的步骤。使用论文真实例子时保留出处；自造小例子标“示意例”，只解释运算或关系，不给它配上虚构实验成绩。类比用于入口，随后落回真实对象，说明类比不能覆盖的关键区别。

例如少样本靶标适应：先让观众看见“新靶标 + 少量已测药物 → 预测其他药物的亲和力”，再展示 support 如何适应、query 如何评价。不能只把 Base Learner、Meta Learner 和 Adaptive Module 放进三个框就算讲清楚。

### 全景后放大，模块必须有作用

- 第一层：对象与任务，输入如何成为输出。
- 第二层：沿总览的主路径解释关键机制，用稳定颜色/位置追踪同一对象；一次放大一个理解障碍。
- 第三层：必要的公式、关键训练信号、约束或消融，解释为什么这个改变可能有效以及原文如何检验。

层次不等于固定三页配额；简单方法可合并，复杂方法可拆更多页。每个核心模块至少让观众知道接收什么、改变什么、输出什么以及为什么需要它。注意区分数据流、监督信号、参数更新与决策反馈，不能画成含义不明的同一种箭头。

公式选影响理解的部分，紧邻解释关键符号对应什么实际对象、输入什么以及约束什么；不能默认同行知道本文自定义的隐状态、聚合向量或损失缩写。必要时配一个示意运算。符号、正负方向、维度、求和范围按原文核对，不用装饰公式制造深度，也不把公式解释变成长段推导。

### 实验应回答方法问题

先写待检验主张，再定位能区分它与替代解释的实验和原图面板。结果页让观众直接找到“为何采用这个设定或对照、看哪个指标、观察到了什么、最多能推出什么”；具体页面写法见 [research-story-and-visuals.md](research-story-and-visuals.md#证据从简)。只有展示遮挡、扰动等评估条件，没有匹配的组件移除或替换对照时，不能据此声称完成了模块消融。

如果用颜色追踪某模块，可在对应消融页沿用该颜色，让方法与证据形成对应。标题和简短标注给出读图方向，保留轴、图例和基线。

## 项目讲解：背景可检索，项目事实来自材料

读取用户提供的 README、设计、代码和真实运行输出，确认任务、数据、架构、实现状态和结果。网上检索补充背景、相关方法和可借鉴机制；不把别人论文的模块或结果写成用户项目已实现。

仅给构想时可完成“项目方案”PPT，清楚标注拟议架构、假设和验证计划。缺少实验结果时展示要验证什么、如何判断成功，不造性能图。已有想法足以做通用方案时，将未定的疾病、数据平台或样本量标为待选条件，继续检索与制作；只有缺失条件会实质改变核心方案时才询问。公开数据集是候选资源，不能写成用户已持有的数据。只有 PPT 请求不意味着需要训练模型、跑大型实验或大规模下载数据。

项目图要区分“已实现”“拟增加”“待验证”；方法解释围绕真实输入、核心对象、关键交互与输出。为了直观可以简化次要细节，但不能删掉改变机制含义的条件。

方案阶段只展开决定可行性的关键选择，保留任务定义、现有路线和验证决策的空间，不为凑深度擅定全部模块与损失。涉及多来源输入时，核实配对/对齐单位、训练与使用时可获得的信息及独立评价单位；这些关系未知时画成带条件的候选路线，不能直接画成已确认的一对一连接。

## 接入个人科研绘图技能

需要定制机制/模型图时，读取 [gpt-image-2-research-studio/SKILL.md](../../gpt-image-2-research-studio/SKILL.md) 及其适用路由和迭代规范。该能力已获用户允许，无需就正常调用反复确认；遵守用户当次预算和限制。技能不可用时用可用原图/可编辑图解继续，并说明限制。

1. **先定义图的教学目标。** 观众看完要理解什么，哪些实体/表示是必要的，关键交互为什么发生，哪些属于未验证设想。不能让图像模型从论文题名自行猜机制。
2. **准备已核对的科学规格。** 输入、对象、表示、核心模块内部作用、输出、连接含义、标签、必要约束与不确定处；提供必要的原文事实和视觉参考，避免无关项目资料。模型主图不能退化为只写模块名的流程框。
3. **按用途绘制。** 整体方法图帮助看全景，机制放大图解释关键关系，示意例帮助理解操作；不要求每张幻灯片都生成图片。科研图遵守绘图技能的原始字节、尺寸和迭代规定，不在本技能重复维护一套生成参数。
4. **实际生成并审图。** 检查对象、连线方向、模块归属、标签和公式；杜撰的连接、伪文字或错误结构必须修正。按其迭代上限处理，不以“图已生成”代替验收。
5. **嵌入后再审。** 保留原始图文件，PPT 中按比例放置不拉伸；检查投影尺寸下标签和重点是否清楚，必要时用原生文字作准确标注，或拆总览和局部。不要在文件层面缩放重写图像来冒充高分辨率；截图和渲染用于 QA，不替代原始交付图。

生成式图只能表达有来源的机制或标明的设想。定量图、原始显微图、分子结构证据和实验结果应取自真实来源或可复现数据工具，不让图像模型补造。PPT 中标明“据原文改绘/机制示意/拟议方案”等实际性质，引用科学内容出处。

## 直观讲解的验收

把“看懂”拆成成品上能定位答案的问题：现有方案在当前任务中为何受限；至少一条核心路径怎样从输入经过运算/目标改变表示或决策；最关键的设计相对什么方案有实质差异；哪项证据支持效用、哪项支持机制、哪些解释仍未排除？未实验的项目方案改查拟议路径、可检验预期和验证设计；相关文献只支持动机，不充当本项目已验证的结果。同时核对输入/输出、主要对象、训练与使用的区别（若适用）。只列模块或只报提升不算讲清楚。关键环节只能找到口号时，先修内容，再做视觉验收；这是一项内部内容检查，不宣称真实受众已理解。

最后按主技能执行全套渲染与逐页 QA，只交付 PPT 及用户明确需要的附加物。
