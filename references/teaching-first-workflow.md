# 以讲解为先：科研论文 PPT 的内容组织与图证讲解

本规范从用户反馈中的讲解失败提炼决策规则，帮助**具有相关基础、尚未读过论文**的听众顺着清楚的问题理解研究。内容顺序与图的可读性决定分页，五种默认版式仅是可复用组件。文中论文案例与页码来自历史反馈，不代表当前执行者已经读取原文或重新检查用户 PPT；复用前须核对对应版本和原图，事实以原文为准。

## 0. 先判论文类型，不能共用同一讲解剧本

| 类型 | 首要主线 | 必须区分 |
|---|---|---|
| 原始方法论文 | 领域技术为何发展到这里 → 既有方法的具体限制 → 本文设计如何逐步解决 → 哪些实验支持 | 设计意图、实现过程、能力实测、组件贡献 |
| 实验研究论文 | 科学问题 → 已有实验证据 → 实验设计/控制变量 → 观察 → 推断及混杂 | 观察相关性与机制因果 |
| 理论论文 | 问题与已有结论 → 关键假设 → 命题及论证思路 → 适用条件与反例 | 已证明结论、推论与经验观察；不硬凑训练和消融 |
| 数据集/Benchmark | 数据采集动机 → 既有数据缺口 → 数据构成/质量 → 评价协议 → 基线和适用范围 | 数据源、标签来源、同源泄漏、评价单位 |
| 综述/观点/愿景 | 领域发展 → 作者如何组织既有研究 → 代表案例分别证明什么 → 尚缺哪些验证 | 作者提出的框架 ≠ 已训练统一模型；引用案例 ≠ 综述自身的实验 |

输入只有论文标题时先核实 publication type。综述没有统一架构的训练与消融，不要强行画“模型输入→编码器→预测→实验验证”的已实现流程，也不要硬凑模型创新和性能提升。

## 1. 用相关进展建立背景，避免无上下文的缺陷清单

为每篇原始方法论文写一个**不出现在页面的研究故事卡**：

1. **领域 / 实验情境**：研究的是谁、典型输入如何获得、输出/生物学问题是什么。给一个可以跟踪的具体对象。
2. **相关进展（按需要选择代表工作）**：说明解决了什么、留下什么限制；核对原文或直接前作。紧凑汇报可只选一个最相关对照，不要求完整历史或固定数量。
3. **当前条件（若适用）**：新的数据规模、测量方式、预测任务、跨设备/跨数据集需求等是什么，为什么旧方案在此条件下失效或成本过高。
4. **关键矛盾**：最核心的一项或少数相互关联的尚缺能力，并标明它如何影响实际任务。不要为了布局并列三个不相干的“痛点”。
5. **本文的回应**：以一个可追踪的技术决定回答矛盾；其他支持性设计留给方法总览。

**内容次序**优先：领域起点 → 代表进展 → 当前矛盾 → 本文思路。不从模型模块数量反推同样数量的“痛点”；确有多项任务需求时可以并列，但要说明它们的实际关联。

### VirTues 讲解参考（非通用固定内容）

空间蛋白组学可以同时测量组织内不同位置的多种蛋白，能观察细胞类型与组织微环境；多重成像与单细胞空间分析逐步提供更丰富的组织读数。早期分析围绕单一实验面板和队列，之后图像编码器/MAE 等方法开始学习表示。**新问题**是不同队列检测的标记物数量和身份都不同，模型还需在高通道数下有效处理空间关系。这才引出 VirTues 的蛋白序列嵌入、分解注意力和汇总 token（使用前核对具体论文版本的引言、模型图及 Methods）。上面的历史是讲解框架；具体代表方法与年份必须来源核实后才能上屏。

不应把“ResNet 与 CA-MAE”无上下文放在页底，令听众先面对陌生方法名。只有解释其原来解决什么、在何种条件下仍不够，以及为什么该对比对本文主张有信息量，才值得展示。

## 2. 先做模型解剖，再制作总览图

本节适用于模型方法论文。从正文/Methods/模型图提取一份简短**模型表**；不适用的项略过，不为填表虚构流程。其他论文按第 0 节改用实验、数据、理论或概念组织图：

| 问题 | 必须记录 |
|---|---|
| 输入是什么 | 实际数据及维度、各模态的身份/时空坐标、缺失值的含义 |
| 最初怎样变成 token/特征 | 切块、嵌入、相加/拼接、位置编码，以及来源 |
| 核心交互或计算 | 具体哪个轴上的注意力、哪些实体可交换信息、关键中间表示 |
| 训练靠什么 | 遮挡方式、预测目标、损失项、监督是否真实可用、更新哪些参数 |
| 推理阶段输出什么 | 哪个模块保留、哪个模块只在预训练使用、如何得到目标结果 |
| 下游怎么用 | 分类/聚合/分割/患者任务分别读取什么，需要什么额外监督 |
| 创新与辅助 | 哪些是论文宣称的新关键设计；哪些只是成熟组件或实现细节 |
| 实验能证明哪些功能 | 真实结果、必要基线、训练/测试划分及限制 |

**主次是强制项。** 从摘要、引言、Methods、Discussion 对照得出真正的核心贡献，不强凑数量；分别定位解释其作用的机制与原文证据。若缺少组件级验证，标为设计意图或作者解释，不补造实验，也不把总体性能当成组件证据。不得只因某模块容易画图就提升为“核心”，也不能把论文重要机制放到角落。

### 总览页优先完整、清晰，而不是展示复杂原图

总览至少覆盖：输入 → 核心表示 → 核心交互/骨干 → 训练或使用方式 → 输出任务。标注哪些是核心创新，辅助模块使用更淡的文字/线条并简要交代。**主路径要完整，但不要求穷举实现细节**：关键机制可以在后续页放大，其余模块在总览页说明功能即可。

如果原始 Figure 过密，可采用：
- 原图全景独立一页（在可阅读尺寸下），旁边只有少量解释；之后用局部面板放大；
- **据原文准确重绘**的可编辑模型骨架作为总览；下一页用原论文的关键局部验证细节；
- 分成两页：主路径（模型结构）和训练/下游分支。两页沿用相同对象和配色。

禁止把原图缩成看不清的小图，再堆三个看似解释了整个方法的抽象标题。原图不是必需的“装饰性证明”。

**新增标签不得遮挡有效图文。** 优先在图片外放标号、画细引线或放大局部；图内确有留白时可加注释，但需渲染确认不遮挡、不改变图意。保留原文已有编号时直接引用，不得挡住原图已有模块、数据、坐标、文字与连线。图片本身分辨率不足时，改成重绘或放大/拆页。

### VirTues 模型总览的重点顺序

- **输入**：每个蛋白通道的空间强度图切块；蛋白的 PLM/ESM-2 序列嵌入表征其身份。
- **核心 ① 蛋白感知 token**：两类表示如何融合，为什么不同面板中同一种蛋白可共享身份。
- **核心 ② Factorized Attention**：同位置的跨蛋白信息交换 vs 同蛋白的跨空间信息交换；说明为何比所有“蛋白×位置”全连接更可控。
- **核心 ③ Patch Summary Tokens**：每位置聚合可见蛋白信息；Masked Autoencoding 使其可用于重建，再为细胞/区域/组织级任务提供向量。
- **训练/推理**：遮挡原始蛋白强度图像并重建；下游按任务聚合且使用对应监督。不能把“缺失蛋白重建”误写成所有临床任务都是自监督完成。

此例用于检查核心设计是否被平均分散或遗漏；实际贡献排序、注意力顺序、融合方式及 Summary Token 的连接关系须以所用版本的原文和代码为准，不把本例直接当作科学规格。

## 3. 关键创新需要再深入一层，但不能替代总览

选择最关键的 1–2 个机制放大。每个机制的讲解必须让听众找到：

`输入对象 → 计算/条件 → 关键中间量 → 输出 → 它相对已有做法为什么重要`

在此之后，才加入确实影响结论的公式、张量维度、复杂度或损失。公式须就近说明关键符号和适用条件；训练阶段或退化情形仅在影响理解时补充，不以公式数量制造深度。

- **机制必要性**：不加这个设计，信息/计算/优化上可能出现什么问题？这是理论分析还是实验证据？
- **实际训练约束**：损失约束了哪些输出，模型是否存在绕过目标信息的捷径？
- **可识别性/信息依赖**：模型能接入某种先验 ≠ 经过实验证明依赖该先验；注意力 ≠ 因果调控。
- **反例/失败**：哪种数据或任务会使这种机制不足？有证据则给原文，没证据明确属于研究推断。

创新页不是方法总览的复述。如果两页只是在用不同词重新解释同一模块，就把创新比较合并到机制放大页。

## 4. 实验页应该教观众读结果，而不是展示审稿模版

按**实验类型**选证据，而不是把实验逐个填进通用“待检验主张/怎样检验/观察结论”三段式：

| 实验类型 | 观众首先要知道 | 不能遗漏 |
|---|---|---|
| 总体性能 | 在哪个数据集、什么任务、对比哪个强基线 | 评价单位、划分、指标方向、实际提升 |
| 消融 | 去掉/替换哪一设计，固定哪些条件 | 是重新训练、推理关闭还是后处理变化 |
| Zero-shot / 泛化 | **完全没见过什么**（队列、蛋白、scaffold、患者或实验条件） | 训练/测试隔离、已见与未见实体分组 |
| 重建/生成 | 给了哪些可见条件，目标信息被怎样隐藏 | 预测和真实图像、指标、简单预测基线 |
| 生物实验/临床 | 测了什么、干预了什么、终点是什么 | 对照/混杂、独立队列、能否支持因果/治疗获益 |

### 正确的读图顺序（画面上可定位）

1. 用一句话交代**为什么做这个实验**（承接前面哪项创新/任务）。
2. 用图上相邻短标注介绍**样本、两个比较条件、横纵轴/颜色、评价方向**。不要在长段文字里解释一张看不清的图。
3. 放大实验的**决定性原图面板**。让观众可以指出哪两个标记/曲线需要比较。一个面板包含太多子图时拆开，一页只聚焦一个重要对照。
4. 在图旁边写**实际观察**（带指标、单位、比较对象）与**这一观察意味着什么**，避免“支持/证明”无对象泛泛而谈。
5. 只在会改变解读时写关键边界，例如 zero-shot 对新蛋白不等于任意蛋白均能重建，生存队列不等于外部疗效验证。

**硬性图证一致规则：** 讲结果的页面必须展示对应的结果图、数值表或根据原文数据忠实重绘的图。**不能左侧放 Fig. 1 模型架构，却在右侧引用 Fig. 2 的性能数作为“实验证据”**；如确需说明模型与结果，必须明确分成不同区块且结果图也要出现，或分两页。

不要重复同一句可迁移/不能保证的摘要；数字需要**基线、条件、方向**，相近但不等价的终点（响应 vs 无病生存）不能合成一次外部验证。

### VirTues 跨队列/未见蛋白例（使用前定位对应版本的结果面板）

以下是用户反馈指出的核查方向；先回原文确认，再据实际结果讲解：
- 什么被留出：Rigamonti 肺癌队列完全不进入一个版本的预训练；另一版预训练包含该队列；
- 什么按类别观察：预训练见过/未见过的蛋白；重点看整通道遮挡时的 Pearson r；
- 图中哪组值得看：分别比较已见和未见蛋白在两种预训练条件下的整通道重建表现；实际数值、聚合方式和指标从原图/源数据读取，不沿用历史稿数字；
- 论文还发现：未见蛋白在 ESM-2 表征空间有接近的已见蛋白时，重建通常更好。**这是泛化条件，不是任意新蛋白保证。**

不要在右侧反复写“待检验主张、怎样检验、观察与结论”这三个抽象标题。图本身无法投影辨读时，保留关键数据用大图或重绘显示。

## 5. 第二篇是综述时，必须改换叙事

用户反馈将 `AIVOs` 归为综述/框架文章；制作时先核对具体文章身份与类型。若确为综述，合理的讲法：
- 虚拟细胞和类器官发展的动机是什么，真实类器官实验目前遇到哪些测量/校准限制；
- 综述如何把多模态状态表示、虚拟仪器和组织尺度机制联系起来；
- 作者引用的 GARMEN / ODFormer 等分别实现了**哪些子能力**，实验系统/任务/输出如何不同；
- 哪些完整闭环构想尚未由**同一个系统**统一实现并验证。

不要画 3 张近似的流程图重复“编码—状态—预测—反馈”，也不要将综述概念误写成论文训练、测试了某个统一模型。若使用示意流程，必须明显标注“综述提出的概念框架”，引用实验须在其本身的论文下解释，不能在标题中暗示“验证 AIVOs”。

## 6. 内容检查与视觉检查各司其职

用户说“重新制作”“背景/方法/实验没讲清楚”时，先依据 [revision-gate.md](revision-gate.md) 判断是否需要**结构性重写**。这类改稿不能通过原版式换词来完成：内容故事板、图的选择与尺度、每项创新的独立解释、实验结果与图证匹配都需要分别复审。

**P0（未修复禁止交付）**
- 原图有效内容被新标注遮挡、核心子图不可读，或架构图被当作实验结果图；
- 方法论文的核心创新被明显漏掉，模型图只讲模块名称而没有关键数据流；
- 综述构想被写成已训练且已验证的统一模型；
- 实验缺失关键比较条件或图与文字的指标/来源不匹配；
- 把设计通路当作被实验确证的因果机制。

**P1（结合任务确认后修改）**
- 背景仅有并列“痛点”，没有领域或前作进展、现实需要；
- 大量重复栏目“待检验主张/作用路径/观察与结论”，文字像英文逐字翻译；
- 多页重复抽象的“数据→编码→预测”流程而不增加新信息；同页不同创新使用完全相同的“主要作用”说明也应重写；
- 每页图和右侧文字无法对应，听众必须靠讲稿猜哪个部分被解释；
- 用不必要或未经核对的对比填充页面。

实际制作分别检查内容与成品：**内容/来源审查**在动手排版之前完成；**投影图文审核**在渲染全部页面之后完成。前者检查研究故事与机制，后者检查图证对应、无遮挡与可读性。模板和机器预警只能帮助发现候选问题，不能代替人眼和原文。
