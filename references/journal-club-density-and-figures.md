# 组会精讲：少页高含金量、原图先行与有效信息密度

针对用户连续多版 VirTues + AIVOs 演示稿的反复反馈。本规范在**组会、论文讲解、双/多篇文献汇报**中优先于通用五版式的页面分配建议；论文事实、引用和图号必须核对原文，不能把本文件案例当作未核对的真实论文内容。

## 0. 不把“详细”误解为增加页面数量

**范围优先**：这里的 9–11 页只适用于论文讲解部分。用户明确要求另行汇报自己的实验时，按 [project-progress-mode.md](project-progress-mode.md) 单独规划项目页并核实实验来源；没有明确要求时，不得自己添加项目页来凑完整组会结构。

生成前必须给每篇论文分配**总页数预算与主次**。当用户未指定时间与页数，且双篇分别为重点原创方法论文和辅助综述时，默认建议 **合计 9–11 页**：
- 重点原始方法论文约 **6–7 页**，含封面、背景、原文完整模型图、1–2 张关键机制页、1–2 张关键实验证据页；机制可合并，按论文难度定。
- 辅助综述或概念论文约 **3–4 页**，含封面、问题与原始概念图、关键框架和**默认至多 1 项必要代表案例**。综述并非原始方法论文，默认不安排性能基准或消融。
- 同类重点论文权重相当时按贡献和理解难度分配，不机械套用上面比例。用户指定更多/更少页时遵从；特别复杂或需要逐图精读时可突破建议范围，但**每增加一页必须说明不可合并的理解障碍**。

用户要求补背景、细讲框架和创新，或两篇都是难度相当的原始研究时，按理解障碍确定预算。可分别为两篇安排「观测任务／前作路线」和「原图全景／局部机制」，必要时拆开。增加的文字应补具体信息流、假设、关键计算或证据解读。保留精选实验规则和投影尺寸，避免用重复总结填页。

**页数预算属于默认约束而非绝对上限**；不要为了达标牺牲真实实验协议、核心图、关键公式或重要科学限定。相反，不能因为论文中有三个实验就自动生成三页。多篇文献不按单篇 4–5 页简单叠加，也不固定每篇 10 页。

## 1. 原图先行：第一次讲模型整体框架，优先作者的原始总图

对于模型方法论文：背景后第一张**总模型架构页以原论文总图（或准确裁切的原图全景）为主要视觉对象**。推荐占主要正文面积，优先原图的 Fig. 1 / overview / architecture 对应 panel；图源放在精简页脚，不要显示“完整模型·据原文重绘”“原文图解/本次标注”等制作过程标签。

在原图周边用少量短的中文说明，按照真实数据流定位：
1. 输入是什么；
2. 编码/骨干在哪里、沿哪些轴进行计算；
3. 哪个位置发生训练监督或解码；
4. 推理/下游读取哪个表示；
5. **用一致的高亮色指明真正的核心创新，不强凑数量**，辅助模块顺着主流程轻带即可。

如原图太密不能全部读清，**仍先展示可辨识的原图总览**，保留真实模块连接与方向，再在下一页放大对应子图；必要时同页上下排原图与简洁辅助概览。图中原有英文允许保留，用图旁短标注解释，禁止直接覆盖原图有效内容。原图不存在、来源未能核实、无法合法获取或在合理放大/拆页后仍无法辨识时，可用核对过的忠实重绘替代，在内部记录例外原因；不能把不可读原图作为形式性的必备页。投影页保留简短来源及必要的“改绘/机制示意”等性质说明。

**原创解释图的地位**：重绘的 token 流、attention 网格、损失路径、复杂度示意是**后续核心机制页的教学辅助**，不是第一张原始模型总图的默认替代品。综述则优先作者的原始概念总图（如适用），但不可把概念框架画成已训练模型。

## 2. 避免“平均主义”：主创新详讲，非核心模块只交代作用

在内部 `storyboard` 中给内容标注：
- **core**：不懂就无法理解论文贡献；配独立机制解释或紧邻图中放大，写出对象/计算/为何有效/训练目标（如适用）
- **supporting**：理解主模型所必需但非核心创新；总览沿主路径一句说明
- **optional**：超参罗列、实现清单、同一结论的多组实验、重复下游任务、次级相关性；默认删去或并入脚注，只有影响结论时保留

不能将每个模块都做独立页。特别是“输入 Token 融合 / 注意力 / Summary Token + MAE / 下游使用”不自动拆为四页；如果整体讲解和创新足够关联，可把 token + summary 在同一机制页讲清，让最关键的 attention 单独放大。

重要：**首次完整模型图必须同时点出创新在哪里**，不必到后面“核心创新汇总”页才揭晓。机制页避免重复同一条总图讲解；需要深入的是为什么这个计算与监督能支持所宣称的能力。

## 3. 证据按决定性选择，不按结果章节数选择

对于一般组会，每篇原始方法论文优先选择 **1–2 个核心实验**；其他指标只在一个紧凑的“补充表现”行或必要时讲。每项实验须有：
- 被检验的核心能力与相关机制；
- 原图关键结果面板或源数据形成的清晰结果表；
- 相匹配的基线/划分/干预条件、指标方向；
- 从图可读出的观察和恰当结论；
- 关键但非泛泛的科学边界。

不能因为论文有“重建 / 跨队列 / 临床响应”三个章节就自动各给一页。若前两项已说明核心能力，临床探索没有直接支撑核心机制、且有复杂患者划分和终点解释，则可精简为一句提及或放弃；反之用户特别强调临床时换掉不相关实验。

综述一般不需要两张不同引用案例各占一页；选最贴近主题的一项说明“已有工作做到哪里”，剩余以一行列表概括，不得伪装成综述自身的实验。

## 4. 有效信息密度：删重复，不仅靠缩字

“更紧凑”指**每页有足够被图证支撑的技术信息**，不等于堆满文本。建议：
- 同一组会封面和大标题不要反复堆满期刊年份、“原始方法论文”“模型重绘”“方法解析”等；保留期刊、论文名和简短来源。
- 主要正文与关键解释保持至少 13 pt，常用 13–15 pt；用户明确允许时可在充分渲染验收后对次要说明降至 12–13 pt，**不降低关键机制图标注、坐标和正文主要层级的可读性**。标题 24–28 pt 可调；来源脚注约 9–10 pt。不得为了页数强行把正文都缩成不可放映的小字。
- 减少同一结论出现于主标题、模块解释、底部横条和下一页的重复。底部横条只留真正必要的结论，不是每页强制添加。
- 辅助标题、重绘说明、脚注中的元信息与内部分析词不要占主视觉空间；原图引用保留简短 `作者·年份·Fig.X` 即可，内部来源账本记录完整版本与图片类型。
- 减少同页三张等宽卡片的模板感；**论文原图 + 对位标注**、**全宽关键机制**、**一个重要实验结果对比**通常更合适。

**必须区分科学透明性与制作痕迹**：投影页仍需可追溯来源、真实/示意/概念的必要性质说明；但“据原文重绘”“原始方法论文”“完整模型”“A/B/C 为本次讲解标注”这类制作性元语言不应作为大号页眉、标题或结论出现。原图、改绘、示意和概念框架的区别仍须在简短图注中按需说明，例如“改绘自 作者·年份·Fig.X”或“机制示意”；不把必要的科学出处作为制作痕迹删掉。

## 5. 页级故事板与删页决策

执行排版前，按每篇论文写：
- `role`: primary / supporting / equal；
- `budget`: 正整数，包含该论文封面；
- `overview_first`: 总模型图出现在哪页、原论文哪一 Figure 面板、可辨认程度及来源路径；
- `core_mechanisms`: 名称、对应总图定位、是否需要独立放大；
- `selected_experiments`: 只保留最有判别力的 1–2 个原始实验（综述可为 0–1 个引用案例）及保留理由；
- `omitted`: 删除了哪些重复模块/实验/背景、为何不会影响主线；
- `slides`: 每页的新增知识、核心图与承载对象、上一页与下一页之间的逻辑衔接；检查器使用下方字段。

供 `check_storyboard.py` 检查时，使用顶层 `papers` 数组；每篇的字段为 `name`、`paper_type`、`role`、`budget`、`available_original_overview` 和 `slides`。顶层 `mode` 为 `journal-club`（默认）或 `deep-reading`；深读不套默认实验数量与双篇页数提示，仍检查自定预算和原图计划。顶层或单篇 `density_reason` 记录合理扩大篇幅/证据范围的理由，检查器跳过对应的默认密度提示，但不跳过自定预算检查；预算调整后应同步 `budget`。单篇 `overview_reason` 记录来源或可读性等原因，允许首张总览采用重绘；仍须有总览计划，不以理由省略它。默认至多一例只针对辅助综述，9–11 页提示只针对重点方法加辅助综述的双篇组合。`paper_type` 跟随 [revision-gate.md](revision-gate.md) 的类型命名。每个 `slides` 项用 `purpose` 表示 cover / context / method-overview / mechanism / evidence 等角色，用 `visual` 区分 original-paper-figure / explainer 等；原图页的 `source` 记录图号与来源，实验证据页用 `experiment_id` 区分实验。同一实验需要多页时复用同一 ID。`overview_first`、`core_mechanisms` 等可保留为附加笔记，不能替代 `slides` 中可检查的计划。最小示例及工具覆盖范围见 [build-and-verify.md](build-and-verify.md) 的故事板检查与脚本开头示例；这些字段只描述计划，不证明已读原文或实际使用图片。

**任何一页未能回答“删除它会损失哪条关键理解或证据？”时，优先合并或删去。** 若一页主要内容是“重复总结”“又一项一般性能”“制作痕迹标签”，一般不该独立存在。模型总览与重要机制页例外：两者虽共享图中对象，但一页讲信息流，一页讲计算细节。

## 6. 基于 1106(3)/(4) 的回归样例

以下来自用户对 `1106(3).pptx` / `1106(4).pptx` 的历史审查反馈，本轮未取得并独立复核这些私人样本；文件哈希、页数和具体页内容不能当作本轮已执行的检查。用户反馈两份文件二进制 SHA256 一致、均为 15 页，VirTues 10 页 + AIVOs 5 页。
- VirTues 第 3 页为**纯可编辑重绘流程，没有论文原始整体模型图**，不符合“原图先行”。该图可改为后续机制页辅助或缩小为右侧示意，不应直接充当原始总图。
- 第 4–7 页各拆出 Token、Attention、Summary+MAE、下游，建议以研究重点决定合并至少一页；第 8–10 页三个实验证据连排，应优先留 1–2 个。
- AIVOs 第 12–13 页都包含数据、状态表示、模型/微环境的概念关系，可比较去重；第 14–15 页两个不同引用案例，优先保留最贴近汇报目标的一例。
- 将“完整模型·据原文重绘”与封面的“原始方法论文”这类制作性标记移出醒目页眉，只保留正常学术页题和必要图源。
- 当前只建议**针对这版做内容选取与结构调整**，不要机械重做已清楚的局部示意、正确的来源或指标。

此示例不代表所有模型论文必须展示某个固定 Fig. 1，不代表“原始图”的使用允许遮挡或未经来源核对的合成。
