# 科研内容到页面

**生成前按 [teaching-first-workflow.md](teaching-first-workflow.md) 判别论文类型，建立理解本文所需的前作与问题联系；模型论文再做模型解剖。**以下页型是可选容器，不是必须填满的固定栏目。实验页面不要机械复制审稿问题三段式。

> **投影文字风格**：本文描述结构与科学论证，最终写入 PPT 前必须按 [chinese-paper-explanation.md](chinese-paper-explanation.md) 把内部审稿语言改成自然的科研讲解。不要把“待检验主张 / 怎样检验 / 观察与结论 / 作用路径”等栏目机械搬上屏幕；用具体问题、运算、结果和可读图示取代。

## 论文讲解：按理解难度组织页面（4–5 页仅为简单论文起点）

页序和必含内容见 SKILL.md 第 3 节；这里说明每页怎样写得既直观又有深度。例子取自示范规格 [examples/flow-matching/spec.json](../examples/flow-matching/spec.json)，只示范写法，不是对其他论文的要求。

### 标题页

- 中文题名写核心改变，不是原题直译。原题 *Flow Matching for Generative Modeling* → “流匹配：把连续归一化流的训练变成回归”。
- 核心想法直接写清研究对象、具体改动及其作用，把关键机制短语加粗；不强套“不再……而是……”句式。按内容选择自然表达，如“在已有任务基础上，通过某种监督/操作，增强某种表示的信息或改善某项预测”。训练与下游使用的区别可另用短句说明。
- 封面只保留方法的核心组合、任务与主要作用，具体的网络输入、后验采样和参数更新在方法页展开。语言应凝练且符合学术习惯，例如“基于计数生成模型的单细胞低维表征学习”；不以更长、更抽象的名词串代替准确解释。
- 首页截图优先用正式发表版 PDF 第 1 页；只有预印本时注明版本号（如 arXiv v2）。不裁改原文内容，不用生成式封面代替。

以 scKITE 的核心想法为例：

> 在表达重建基础上，**通过细胞描述与 TF–靶基因程序的联合生成监督，增强表达表征的生物学语义与调控信息**；下游仅保留表达编码器。

这句话指出了基础任务、增加的监督及其作用对象，比“把预期下游能力写进训练目标”更明确。后续方法页再解释细胞描述的来源、TF–靶基因程序所指的基因集合，以及生成损失如何更新编码器。此例示范表达方式，不要求其他论文采用同类监督；“增强调控信息”也不等于证明调控因果。

专业表述要准确、具体，不必改成口语或增加大段解释。若关键句仍依赖“这个能力”“这些知识”“相互协同”等泛指才能成立，补出对应对象与操作；效果未经检验时，用“旨在/希望增强”说明设计意图，不把目标直接写成已证实的机制收益。

### 背景与问题

- **研究场景与发展脉络**：说明当前任务如何由已有测量/建模进展引出，以及原有路线在哪个新条件下受限。只保留理解本文所需的相关前作，不要求从领域起源开始；作者与年份须有来源。用必要的输入/输出例子连接问题，不把背景缩成“3 个痛点—3 个模块”对仗图。
- **已有工作**：按需要选与本文最相关的路线，不强凑数量或按年份罗列。每条写“用什么信息或目标做什么、已经做到什么、在哪个条件下仍不够”。保留前作的真实成就，不为衬托本文制造失败；区分原文已证明的不足和本文提出的新假设：未显式优化某能力不等于完全不具备，换一种目标也不自动胜过旧方法。
- **问题与本文回应**：把最重要的 1–2 个困难写成“什么条件使现有做法受限、造成什么具体后果、本文哪项设计针对它”。例如面板变化先说明通道身份或缺失标志物如何影响复用，再指向本文的输入表示设计；仅写“数据异质、需要统一表示”不够。背景页给出设计名称及作用方向，具体运算留到方法页；已知不足、作者动机与待证实假设按来源区分。
- 反例：“传统方法存在局限，深度学习方法发展迅速。”正例：“最大似然训练 CNF 每次迭代都要数值求解 ODE 并反传，难以扩展到高维图像。”

### 方法与实现

- 导语承接背景页“本文思路”，具体解释建模与推断过程。区分“用概率分布刻画数据变异”与“直接去噪”、“非线性生成映射”与“非线性推断”等不同概念。
- 流程每步写“接收什么 → 做什么 → 输出什么”，3–5 步；训练与推断分开；最关键的一步标出。只放模块名和缩写不算讲清楚。
- 公式只放一条能说明关键目标或约束的；旁注说明符号对应的实际对象，以及它为什么成立或为什么这样设计。若省略变量或目标项，标明简化；若已解析边缘化辅助变量，说明该处理，不误称完整边缘目标遗漏了潜变量。不能把另一版本模型的变量补进当前版本。
- 长公式可用已定义的 q、p 等符号简写，把完整分布定义移到相邻说明，保留原目标的含义与优化方向。实际渲染后检查整式是否完整、末尾括号是否独占一行；必要时调整区域或适当减小公式字号，不能仅据文字测量结果判定通过。介绍编码器时保留“近似后验”，不要为凝练而省成精确后验。
- **沿图讲解**：先选能串起输入、关键计算和输出的模型图。每段解释有可指认的图上锚点（模块名、编号、箭头或高亮区域），就近说明该处接收什么、执行什么、产生什么；公式和变量放在对应运算附近。把原图放左侧、右侧写几段不指向具体位置的概述，不算图解。
- **总览与局部**：总览保留真实输入、各核心创新及必要辅助模块、训练/推断分支和下游任务；**明确哪些是主创新，哪些只是支持组件**。组会先展示可辨认的作者原始总图，再放大关键局部或用可编辑示意解释计算；原图无法获取或严重不可读时，按组会规范记录原因并忠实重绘。不得叠加 A/B/C 或编号遮挡原图重要文字、箭头、模块或实验点。需要时跨页延续同一图，不把所有说明挤进一页，也不在图解后另放一套内容相同的纯文字流程。引用原图时保留所解释面板的完整边界、图例和必要标签。
- 区分数据流、监督信号、参数更新和反馈；结构上存在的通路不等于模型实际依赖它。

### 关键创新

- 按原文选择核心贡献，不强凑数量；每条在同一维度比较“已有方法 → 本文改进”，说明“主要作用”。标题直接点出技术改变；区分设计提供的能力、计算代价解释与已验证结果。
- 创新可以是新机制、新组合方式、新适用条件或新发现；不要把注意力、残差、数据增强等常见模块包装成独有创新。
- “主要作用”与证据强度匹配：作者论证写“作者认为”，有实验支持就给一个数字；同期工作提出相近想法时如实说明。整体性能不能代替各组件的独立贡献证据。
- 方法页讲“怎么运作”，创新页讲“为什么这样选、相对谁不同”。去掉标题后两页若仍是同一段模块介绍，删掉重复，把空间留给前作比较和作用路径。

### 证据（从简）

- 结果图是讲解中心，而不是审稿栏目：**不得使用“架构图＋结果数字”冒充结果展示；每项结论要对应真实结果面板或源数据重绘图**。每个选中的实验围绕一个科学问题组织，内容必须能回答：**检验什么、怎样比较、读哪个指标、实际发现、不能推出什么**。这是内部验收清单，**禁止把这五项固定为每页五个审稿栏目**。投影页优先放大结果面板，并在对应位置直接写比较条件和观察。
- **检验方式**交代决定推论的划分、干预或对照：保留什么、改变什么、与谁比较，为什么该设计能检验当前主张。主实验检验总体效用，组件消融检验对应设计的贡献，外部验证检验迁移范围；只保留必要设定。
- **读图与结论**：选能回答主张的原图面板并放大，标出读哪条曲线、哪组柱或哪两个图像；解释指标如何反映目标能力及方向。写出实际差异，再说明支持什么、仍不能推出什么。图注保留数据、图号、条件和单位，不放整张大表。
- 输入遮挡、噪声或分布变化等测试可检验可用信息与稳健性；不同难度下的分数差异不能直接归因于某模块。声称模块或训练目标有效，需要匹配的移除、替换或训练对照；没有该对照就限定结论。

### 页间衔接

衔接靠具体对象和问题的承接，不靠页尾机械添加“因此”或“下一页”。检查这条链能否从成品读出：

已有工作没有解决什么 → 本文构造了什么目标或结构 → 它怎样作用于表示或决策 → 用什么任务和对照检验 → 结论回到最初的问题。

同一对象、变量和例子跨页保持同名、同色；背景介绍的前作在对应机制或创新比较处回指，不绑定固定页码。

## 其他任务

**默认论文任务仅包含论文内容**。不得因用户上传的既往组会稿含项目结果而自动追加项目页。用户当前明确要求“论文＋本轮实验”或独立“项目进展”时，才按 [project-progress-mode.md](project-progress-mode.md) 使用用户指定的真实实验文件、明确划分和结果来源，并与引用论文的证据分区。项目结果的负结果、开发集指标和数据泄漏风险不能被美化为已验证结论。


综述从研究领域及已有技术演进讲起，按“发展与未解问题—作者对现有研究的组织框架—各引用案例分别实现了什么—尚未统一验证的能力”组织；**不得把引用案例写成综述框架自身的实验，更不得画成已训练的单一系统**。框架图说明作者提出的组织方式，引用案例的模型与实验注明原研究及适用体系；不能把多个案例拼成一个已训练、统一验证的模型。没有总体实验时，明确框架尚待验证，不为凑实验页捏造结果。

进展组会按用户要求决定是进展、经验复盘还是方案讨论。经验复盘呈现原假设、实际尝试、结果与获得的认识；不要自动加未来路线。失败结果可以是主证据，写清停止的是哪项假设、哪些结论仍未知，区分训练准入失败、开发评估负结果与尚未运行的实验。

调研/开题用统一比较维度组织文献，如输入、可用监督、模型作用、评价协议、局限和迁移条件。不要每篇论文都重复同样三页摘要，也不要拼一张读不清的大表；按需要拆成概览和重点机制。多篇论文逐篇讲解时，每篇独立决定深度，简单论文可从 4–5 页结构开始。

非论文结构的页面按内容选用：

| 内容 | 直观表达 | 最小必要信息 |
|---|---|---|
| 任务定义 | 一个具体输入/输出例子或映射 | 预测对象、已知信息、输出含义 |
| 现有缺口 | 并列对比或问题链 | 已能做到什么、尚未满足的能力、适用条件或实际代价 |
| 方法总览 | 主路径与必要分支 | 输入、关键变换、输出；训练/推断区别 |
| 模块创新 | 前后对照或局部放大 | 原方案、改变、预期/已验证作用 |
| 结果 | 放大的关键图或精简表 | 指标方向、基线、协议、观察、结论范围 |
| 消融 | 模块移除对比 | 固定条件、去掉什么、性能变化 |
| 局限 | 证据与边界并列 | 结论成立条件、不能推出什么 |
| 下一步 | 小型决策图或验证路线 | 假设、实验、成功/失败判据、需讨论事项 |

配方不是页数配额；一页可以合并简单内容，复杂方法可能需要总览加局部。

## 长段文字如何改

原始材料：“模型对 Reference 和 Query 复合物分别编码，得到包含蛋白环境的配体表示，池化后求差，预测相对亲和力，并交换输入进行数据增强。”

可拆为：

1. 方法总览：两个有明确标签的复合物输入，共享编码器，两路池化，在“表示求差”处汇合，输出 Δ亲和力。用短注释说明共享参数。
2. 关键机制：放大输入交换与差值变号的对应关系，说明其约束。公式和符号方向须按实际来源核对。

这比在整张原图右侧塞入长段文字更容易追踪。若原图已足够清晰，保留它并加少量相邻标注，不必重复重画。

## 科研证据检查

- 明确数据集、划分、样本/重复、评价协议、指标方向和基线。报告自己的实验时保留实际运行与输出来源。
- 少样本 support 数量、未见靶标划分、冷启动/随机划分等可能决定结论，应在结果附近标注。
- 区分绝对提升、相对提升和百分点。例如 20% 到 30% 是 +10 个百分点或相对 +50%。
- 每个醒目数字附近注明相对谁、指标含义与方向；不能依赖另一个数字的说明或远处页标题来消除歧义。必要时交代样本单位及聚合口径，不把细胞数、聚合表达谱数、受试者数等混作同一数据规模。
- 区分计算筛选、功能实验、外部验证和临床效果；相关性、预测提升和机制因果不能互换。
- 生信图保留条件、图例和量纲：UMAP 不代表谱系因果，注意力图不自动等于机制解释；AUROC、AUPRC、IC50、ΔΔG 等按当前任务准确解释，不套万能结论。
- 引用紧邻被支持的图或结论，至少可追溯到作者/年份及图号或 DOI；原图、重绘、改绘和自有实验区分清楚。
- 给出 DOI、标题或项目描述时，主动检索完成解释所需的原文、背景和相关材料；范围以支撑 PPT 为准，不擅自扩成全面文献调研或新的科研实验项目。
