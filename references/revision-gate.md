# 论文 PPT 的结构性改稿闸门（生成质量回归）

本文件针对“旧版被指出讲解结构有问题，新版只是改词/移除编号”的失败模式。用于**明确要求重做研究故事、模型图或实验图**的任务；如果用户仅要求小范围措辞或格式修改，不应用“新旧图片完全相同”否决正确的小修。

## 一、任务开始前，先判断改动属于哪一级

| 改动级别 | 用户意图 / 失败模式 | 通过标准 |
|---|---|---|
| L1 文案局部修改 | 修错字、替换术语、删除遮挡标签 | 目标对象修复、不误改别页即可 |
| L2 讲解质量重写 | 背景没有发展脉络、模型图看不懂、创新未区分主次、实验讲不清楚 | 针对受影响内容重新规划叙事、图文关系与必要的布局，并逐项验证问题已解决；不自动重做整套 |
| L3 整套重构 | 论文类型、目标受众、信息组织或参考布局整体错误 | 可以重排、增删页和图，按重新生成完整课件验收 |

当用户要求 L2/L3，先把反馈转成可检查的内容缺口，不直接复制旧稿逐页改词。图片、位置或页数不变并不等于失败；改变它们也不等于成功。以听众能否追踪具体机制、读懂对应证据为准，合适的原图和已认可内容可以保留。

## 二、先出内部「故事板」，再运行 PPT 构建

组会精讲和多论文合并时，按 [journal-club-density-and-figures.md](journal-club-density-and-figures.md) 额外记录每篇论文的 `role`、`budget`、`overview_first`（原文总模型图来源/位置）、`selected_experiments`（决定性 1–2 项）和删除项。


在 `work/storyboard.json` 或等价文件，**按每篇论文**记录：

- `paper_type`: original-method / experiment / review / benchmark / theory；
- `field_story`: 理解本文必需的研究场景、相关前作、尚缺能力与本文回应；不强凑新条件或完整领域史，每项事实来源可追溯；
- `one_sentence_takeaway`: 不依赖模型缩写的核心想法；
- `core_contributions`: 每项贡献的对象、具体改变或论点、原文位置和对应证据；缺少组件实验时标明设计意图，不用总体性能替代；
- `method_map`: 模型论文记录输入、核心计算、训练/推断与输出；实验、综述、理论等按论文类型改为实验设计、概念组织或论证关系，不硬填模型字段；
- `slides`（等价文字计划也可；运行检查器时按组会规范字段组织）: **为什么必须有这一页、听众在此处新增理解了什么、选哪张图、图讲的是否恰好是该页结论**；重复解释页或低优先级实验页应合并删除；
- `visual_evidence`: 精确到 figure 和 panel 的出处；有定量结论则对应结果图或真实数值表；
- `omissions`: 删除与辅助化的内容及其理由；复杂创新不允许只给三个标签不解释。
- `revision_map`（改稿时）：每项反馈对应旧页/对象、缺失理解、所需原文或图表、新页/对象与验收办法。完成后补实际检查结果；重排时记录新旧页对应，不能按相同页码强行比较。

这些是制作前的内部证据，不强制添加到 PPT，也不作为额外交付。

**进入制作的条件**：每个影响理解的反馈都有具体内容修复和验收办法，关键主张能定位来源与对应图证。模型总览能追踪真实信息流，其他论文按其类型检查；不能只写“补背景、讲清机制”等待办。关键来源暂缺时标记受影响部分，继续可独立完成的页面，不编造内容。

## 三、成品出现以下问题必须返工

1. **旧内容残留**：删掉 A/B/C 图上标注后，图注仍写“A/B/C 是本次讲解标注”，或解释仍指向已经不存在的箭头/框。这是独立的跨对象一致性错误，不是风格意见。
2. **创新内容复制**：为满足“补一个创新点”，直接复用上一创新的 before/after/why，导致不同设计没有得到解释。每项贡献应说清其独特改变；多个设计可能服务同一对象或目标，不强造不同收益。
3. **图证错配**：标题说“PCC 提升”，可见主图却是架构图；可列架构背景，但真正对应的实验结果图或数值表必须出现。
4. **图像充当占位符**：全景模型图虽有来源，却缩到无法辨识；旁边几段文字不指向图的具体模块或箭头。
5. **综述伪装统一实证**：综述中的 UR/VI/仿真/校准作为提出的框架展示；引用研究只能证明各自子任务，不得拼成同一研究已实现的完整闭环。
6. **机械语言修复**：仅把“待检验主张”换成“先……”，没有补具体实验条件、可见指标和读图关系。

## 四、自动检查：报告候选问题，不伪称已做科学验证

运行：

```bash
python "SKILL_DIR/scripts/review_deck.py" "OUT/主题-完成版.pptx" --output "OUT/work/review.json"
python "SKILL_DIR/scripts/review_deck.py" "OUT/主题-完成版.pptx" --baseline "INPUT/旧稿.pptx" --output "OUT/work/revision-review.json"
```

输出包含：

- `duplicate_explanation`: 同页长句在多个文字对象中重复（提示复制说明或挤占空间）。
- `orphaned_annotation_reference`: 图注还在说明自加 A/B/C 标注，但文字对象中已没有完整的一组；图片本身可能含字母，因此需视觉核查。
- `mixed_architecture_and_metric_evidence`: 架构图的语言与实验指标并存；**只提示图证可能错配**，不能断言确有错误。
- `revision_comparison`: 新旧页数、文本变化、图片二进制哈希和位置、整体形状几何。这些只是变化线索，不能判定语义修复：重新编码同一张图可能改变哈希，可编辑重绘未必计入图片，重排会使同页码对比失配。结合 `revision_map` 和实际渲染逐项验收；不设变化比例、换图数量或增页门槛。

**此脚本不是语义模型、不是 OCR，也无法识别图片内的论文内容；不能根据“0 个预警”宣布论文讲解通过。**

## 六、人工完成条件

最终渲染每一页（不是只看提取文字），用原图与所选论文版本对照，逐项关闭 `revision_map` 中的问题；记录新页/对象、来源、可读性与图证检查结果，未解决项明确标记。至少对一个代表性结果页进行内部读图审核：能否指出比较条件、结论对应的数据与尚未证明之处。真实观众评测可选，没有实际评测时只称“内部可读性审核”，不得声称“经听众测试”。
