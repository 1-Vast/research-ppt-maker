# 用户明确授权的项目实验进展汇报模式

## 1. 根据本次交付确定范围

**只收到 DOI、论文标题、PDF、文献列表或“制作论文组会 PPT”时，不得自行加入用户项目实验、当前研究结果、下一步计划或研究设想。** 不能依据模型记忆、历史示范稿、同项目其他对话，擅自把“项目进展”理解为本次汇报范围。

用户要求“最后加入当前工作”“结合我的实验结果”等内容时，用 `paper-plus-project`。仅要求汇报自己的研究进展时，用 `project-only`。原稿是修改对象且用户要求保留其余内容（包括只改指定页、只改语言或保持全套内容）时，原有项目页属于保留范围，仍按实际交付范围选择 `scope`；不由此扩大到新增结果、重新解释项目实验或更新数据。若旧稿仅用作版式参考，则只借用版式。用户说明某页是自己补充的，仅用于厘清归属。

## 2. 信息来源与使用边界

项目实验事实仅使用本次指定的真实实验记录、用户提供的表格、代码日志、运行产物或明确引用的已连接项目文件。历史 PPT 可作为用户本次明确选用的来源，但必须记录其实际读到的内容，不能补造没有核实的模型训练或结果。

项目侧内部记录每项实验：
- 研究问题与假设；
- 数据集、样本单位、划分、是否开发集或独立测试；
- 主模型、匹配基线、控制变量、训练预算；
- 核心指标、结果数值、随机种子/重复或置信区间（仅报告实际有的）；
- 观察、可支持的结论、失败解释与后续待测项；
- 文件名、日志或源数据定位，必要时附 SHA/版本。

未运行的模型与实验必须标明“拟议/待验证”，不能与已经得到的观测结果并列成“实验结果”。验证集上的结果不得表述为测试集或真实临床效果。

## 3. 页数规划：论文预算与项目预算分开

可用故事板示例（仅示意字段）：

```json
{
  "mode": "journal-club",
  "scope": "paper-plus-project",
  "project_authorized": true,
  "papers": [{"name":"Paper A", "paper_type":"original-method", "role":"primary", "budget":2, "available_original_overview":false, "slides":[{"purpose":"context"},{"purpose":"method-overview", "source":"Methods", "visual":"redraw"}]}],
  "project_slides": [{"purpose":"progress", "source":"用户提供的实验日志或结果文件"}]
}
```

在 `work/storyboard.json` 顶层声明 `scope: "paper-only"`（默认）、`scope: "paper-plus-project"` 或 `scope: "project-only"`。`mode: "journal-club" / "deep-reading"` 仍只控制论文讲解深度。交付含项目页时，按第 1 节核实本次请求所允许的范围，再记录 `project_authorized: true`；该字段只记录判断结果。项目页独立列入 `project_slides`，记录来源和角色。重点方法与辅助综述的紧凑汇报中，9–11 页预算只计论文部分；若用户指定整套页数或时长，在其限制内分别分配两部分。

默认没有项目授权时，`project_slides` 必须为空或不存在；若用户仅要求项目进展，可用 `scope: "project-only"`、`papers: []` 和有真实来源的 `project_slides`；不能因为上传 PPT 中曾有项目实验页，就自动复制到新稿。授权后项目页数取决于用户已有的真实进展、汇报时间与研究重点，通常精简为 2–4 页但不是硬上限。

## 4. 项目页的推荐顺序（只在授权后使用）

- **项目任务与本轮假设**：当前要预测什么，输入/输出、数据与划分是什么；和所讲论文的联系仅作为背景，不把论文方案写成自己已实现。
- **最有判别力的实验对照**：一张表或图列出本人实际运行的主要方法、强基线、指标、比较条件。优先选负结果和决定是否继续的实验，不为凑正向故事线只选效果好的结果。
- **解释与决策**：改善幅度相对随机波动有多大；是否排除预训练无关、信息捷径、数据泄漏或更简单模型的替代解释；哪些结论只适用于开发划分。
- **下一步（可选）**：用户明确要求方案/讨论时，给成本最低、能证伪核心假设的验证实验，明确成功、失败、停止条件；未要求则不自动追加。

引用研究和项目实验必须有视觉分隔：独立的页眉/区段、项目数据来源、模型版本与评价协议。不能把文献的性能数字放进项目结果表中冒充本人实验，也不能混用“论文作者结论”和“本轮实验观察”。

## 5. 三类生成质量红线

- 默认 paper-only 生成了任何项目实验页：**P0，不应交付**。
- 获授权加入的项目实验缺乏真实来源，或数值、数据划分、验证层级被改写：**P0，不应交付**。
- 项目结果已有真实负结果，却自动改写成“模型验证成功”“证明可行”：**P0，不应交付**。

## 6. 回归样本边界

据用户对 `1106(6).pptx` 的历史审查反馈，第 12–13 页是单独的项目进展；本轮未独立复核该私人稿件。实际制作时按本次请求判断交付范围，并区分保留原页与新增或更新项目实验。
